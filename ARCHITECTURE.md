# Архитектура системы "Стрелец"

## Обзор

Стрелец - это распределенная система для проведения онлайн-аукционов в реальном времени, построенная на микросервисной архитектуре с использованием event-driven подхода.

## Архитектурные принципы

1. **Микросервисная архитектура** - каждый сервис независим и может масштабироваться отдельно
2. **Event-driven** - асинхронная коммуникация через Kafka
3. **CQRS** - разделение моделей записи и чтения
4. **Saga паттерн** - для распределенных транзакций
5. **Идемпотентность** - все операции идемпотентны
6. **Горизонтальное масштабирование** - каждый сервис может масштабироваться независимо

## Компоненты системы

### 1. API Gateway
- **Технология**: Go, Gin
- **Порт**: 8080
- **Функции**:
  - Единая точка входа
  - JWT аутентификация
  - Rate limiting (token bucket)
  - Маршрутизация запросов

### 2. Budget Service
- **Технология**: Go, gRPC, PostgreSQL
- **Порт**: 50051 (gRPC)
- **Функции**:
  - Управление балансами пользователей
  - Резервирование/списание/освобождение средств
  - Оптимистичные блокировки (versioning)
  - Saga для распределенных транзакций

### 3. Bidder Service
- **Технология**: Go, HTTP REST, Redis
- **Порт**: 8081
- **Функции**:
  - Прием и валидация ставок
  - Идемпотентная обработка (Redis)
  - Circuit Breaker для Budget Service
  - Retry с экспоненциальным backoff

### 4. Auction Engine
- **Технология**: Go, Kafka Consumer
- **Функции**:
  - Проведение аукционов
  - Поддержка First-price и Second-price (Vickrey)
  - Определение победителя
  - Таймеры завершения аукционов

### 5. Notification Service
- **Технология**: Go, WebSocket, Kafka Consumer
- **Порт**: 8083
- **Функции**:
  - WebSocket соединения для клиентов
  - Уведомления в реальном времени
  - Потребление событий из Kafka

### 6. Analytics Aggregator
- **Технология**: Python, Kafka Consumer, ClickHouse
- **Функции**:
  - Агрегация метрик в реальном времени
  - Экспорт в ClickHouse
  - Подсчет CTR, win rate, средняя цена

## Потоки данных

### Поток ставки

```
1. Клиент → API Gateway → Bidder Service (HTTP)
2. Bidder Service → Budget Service (gRPC): Резервирование средств
3. Budget Service → PostgreSQL: Атомарное обновление баланса
4. Bidder Service → Kafka: Событие BidSubmitted
5. Auction Engine (consumer Kafka) → Обработка ставки
6. Auction Engine → Kafka: Событие BidAccepted/BidRejected
7. Notification Service → Клиент: Результат через WebSocket
```

### Поток завершения аукциона

```
1. Auction Engine → Определение победителя
2. Auction Engine → Kafka: AuctionFinished
3. Budget Service (consumer) → Финальное списание средств
4. Notification Service → Уведомление победителю
5. Analytics Aggregator → Обновление агрегированных данных
```

## Базы данных

### PostgreSQL
- **Назначение**: Транзакционные данные, бюджеты
- **Таблицы**:
  - `balances` - балансы пользователей
  - `reservations` - резервирования средств

### Redis
- **Назначение**: Кэш, идемпотентность, распределенные блокировки
- **Использование**:
  - Хранение idempotency keys
  - Кэширование частых запросов
  - Rate limiting

### ClickHouse
- **Назначение**: Аналитика и агрегация в реальном времени
- **Таблицы**:
  - `auction_events` - события аукционов
  - `auction_metrics` - агрегированные метрики

## Message Broker

### Kafka
- **Топики**:
  - `auction-events` - события аукционов
  - `bid-submitted` - отправленные ставки
  - `budget-events` - события бюджета

## Мониторинг

### Prometheus
- Сбор метрик со всех сервисов
- Хранение временных рядов

### Grafana
- Визуализация метрик
- Дашборды для мониторинга

### Jaeger
- Распределенная трассировка
- Отслеживание запросов через сервисы

## Гарантии консистентности

### PACELC компромиссы

- **Бюджетные операции**: PC/EC (Консистентность важнее задержки)
- **Прием ставок**: PA/EL (Доступность важнее, eventual consistency допустима)
- **Аналитика**: PA/EL (Можно потерять часть событий, но система должна работать)

## Масштабирование

Каждый сервис может масштабироваться независимо:
- **Bidder Service**: Горизонтальное масштабирование для обработки большего количества ставок
- **Auction Engine**: Масштабирование для большего количества аукционов
- **Budget Service**: Вертикальное масштабирование для большей нагрузки на БД

## Отказоустойчивость

- **Circuit Breaker**: Защита от каскадных отказов
- **Retry**: Автоматические повторы с экспоненциальным backoff
- **Health Checks**: Проверка здоровья сервисов
- **Graceful Shutdown**: Корректное завершение работы

## Безопасность

- **JWT аутентификация**: В API Gateway
- **Rate Limiting**: Защита от DDoS
- **Input Validation**: Валидация всех входных данных
- **SQL Injection Protection**: Prepared statements
